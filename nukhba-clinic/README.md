# مجمع نُخبة الطبي — نظام إدارة مركز عيادات

نسخة عرض (اسم وهمي) لنظام متكامل لمركز عيادات طبية: موقع عام للحجز، بوابة للمريض، لوحة للطبيب، مكتب استقبال وطابور انتظار، فوترة وتأمين ومطالبات، وموارد بشرية ورواتب وعُهد.

**التقنيات:** Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS · Supabase (PostgreSQL + Auth + Storage) · Vercel

---

## الواجهات

| الدور | المسار | أهم الوظائف |
|---|---|---|
| الموقع العام | `/`, `/clinics`, `/doctors`, `/book`, `/careers`, `/verify` | العيادات والأطباء وتقييماتهم، شركات التأمين المعتمدة، طلب حجز بدون حساب، الوظائف، التحقق من الإجازات المرضية والتقارير برمز QR |
| تسجيل مريض | `/register` | فتح ملف جديد برقم الهوية/الإقامة (لا يُسلَّم ملف موجود لمن يكتب رقمه) ثم الدخول مباشرة للحجز |
| المريض | `/patient` | الحجز الذاتي بالأوقات المتاحة فعليًا، الإلغاء والتأجيل ضمن المهلة، الزيارات والوصفات والنتائج المعتمدة، الإجازات والتقارير، الفواتير، تقييم الزيارة، تحديث بيانات التواصل |
| الاستقبال | `/reception` | لوحة اليوم لكل طبيب، الحجز نيابة عن المريض، تسجيل الحضور ورقم الدور، عدم الحضور، طلبات الحجز من الموقع، ملفات المرضى وحسابات البوابة، شاشة الطابور `/reception/queue` |
| الطبيب | `/doctor` | طابوري اليوم، بدء الكشف، العلامات الحيوية، التشخيص ICD-10، الوصفة، طلب التحاليل والأشعة، ملاحظات خاصة لا يراها المريض، إصدار إجازة مرضية/تقرير/تحويل، توقيع الزيارة، النتائج، جدولي وإجازاتي |
| الحسابات | `/billing` | فاتورة تلقائية عند الحضور، إضافة خدمات، توزيع المبلغ بين المريض والتأمين (نسبة تغطية + حد أعلى للتحمل)، ضريبة 15% لغير السعوديين، فاتورة ضريبية برمز ZATCA، تحصيل وإلغاء دفعات، المطالبات، شركات التأمين، قائمة الأسعار، التقارير |
| الإدارة | `/admin` | لوحة مؤشرات، العيادات، الأطباء وجداولهم وحساباتهم، الفريق، الإعدادات والهوية، الخصوصية وسجل التعديلات |
| الموارد البشرية | `/hr/...` | الموظفون، الحضور بالموقع، الإجازات والطلبات والاعتمادات، الخطابات القابلة للتحقق، العُهد، مسير الرواتب |
| الموظف | `/me` | البصمة، الإجازات والرصيد، الطلبات، العُهد، كشف الراتب |

العربية (RTL) افتراضية مع تبديل فوري للإنجليزية، وتصميم متجاوب للجوال.

## الأمان

- **RLS على كل الجداول**: المريض لا يرى إلا ملفه، والطبيب يرى ملفات مرضاه فقط، والاستقبال لا يرى السجل الطبي، والحسابات لا ترى التشخيص إلا لأغراض المطالبة.
- سير العمل (الحجز، الحضور، الكشف، التوقيع، الفوترة، الدفع) يتم عبر دوال `SECURITY DEFINER` تتحقق من الدور والحالة، وليس بتحديث مباشر للجداول.
- لا تظهر الزيارة ونتائجها للمريض إلا بعد توقيع الطبيب، والملاحظات الخاصة لا تظهر له أبدًا.
- الملفات الطبية في Storage خاصة وتُفتح بروابط مؤقتة.
- الدور يُقرأ من `app_metadata` — لا يستطيع المستخدم رفع صلاحيته.
- سجل تعديلات للجداول الحساسة، وسياسة خصوصية وحقوق أصحاب البيانات وفق نظام حماية البيانات الشخصية.

## خطوات التشغيل (رفع يدوي)

### 1) GitHub
1. أنشئ مستودعًا جديدًا خاصًا (مثلًا `nukhba-clinic`).
2. فك الضغط عن الملف وارفع محتواه كما هو (المجلدات `src`, `supabase`, `public`, `scripts` والملفات في الجذر).
   - من الموقع: **Add file → Upload files** واسحب كل المحتوى، أو من الجهاز:
   ```bash
   git init && git add . && git commit -m "Initial commit"
   git branch -M main && git remote add origin https://github.com/<you>/nukhba-clinic.git && git push -u origin main
   ```

### 2) Supabase
1. أنشئ مشروعًا جديدًا (المنطقة المقترحة: أقرب منطقة متاحة لك).
2. افتح **SQL Editor** وشغّل ملفات `supabase/migrations` **بالترتيب** (من `…0001_core.sql` حتى `…0019_hardening.sql`)، كل ملف في استعلام مستقل.
3. (اختياري للعرض) شغّل `supabase/seed/demo.sql` لإضافة عيادات وأطباء ومرضى ومواعيد وفواتير تجريبية.
   قبل التشغيل الفعلي احذفها بـ `supabase/seed/demo-purge.sql`.
4. **Authentication → Sign In / Providers → Email**: فعّل Email، وأوقف **Confirm email** (التسجيل يتم من الخادم ومؤكَّد مسبقًا)، وأوقف **Allow new users to sign up** (التسجيل الذاتي للمرضى يمر عبر الخادم فقط).
5. **Authentication → URL Configuration**: ضع رابط الموقع في **Site URL** وأضف `https://<domain>/**` في **Redirect URLs**.
6. من **Project Settings → API** انسخ: `Project URL` و `anon key` و `service_role key`.

### 3) Vercel
1. **Add New → Project** واختر المستودع (الإعدادات الافتراضية لـ Next.js تكفي).
2. أضف متغيرات البيئة:

| المتغير | القيمة |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon key |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key (سري) |
| `NEXT_PUBLIC_SITE_URL` | رابط الموقع، مثل `https://nukhba-clinic.vercel.app` |
| `CRON_SECRET` | نص عشوائي طويل |

3. Deploy. المهمة اليومية `/api/cron/daily` معرّفة في `vercel.json` (تذكير المواعيد، تصعيد اعتمادات الموارد البشرية، إرسال الرسائل، حذف البيانات المنتهية).
4. الرسائل الخارجية (SMS / واتساب / بريد) اختيارية — راجع `.env.example` و `src/lib/notify/providers.ts`.

### 4) أول مدير (إن لم تشغّل بيانات العرض)
```bash
cp .env.example .env.local   # وعبّئ القيم
npm install
npm run create-admin -- admin@clinic.sa "اسم المدير"
```
يطبع كلمة مرور مؤقتة يُطلب تغييرها عند أول دخول. ومن `/admin` تُنشأ العيادات والأطباء وحسابات الفريق.

| الدور | البريد |
|---|---|
| المدير | `admin@demo.example.com` |
| الاستقبال | `reception@demo.example.com` |
| الحسابات | `accountant@demo.example.com` |
| الموارد البشرية | `hr@demo.example.com` |
| موظف (تمريض) | `nurse@demo.example.com` |
| طبيب | `doctor.khalid@demo.example.com` (وكذلك `doctor.reem`, `doctor.faisal`, `doctor.haifa`, … ) |

```bash

npm run typecheck

```

## هيكل المشروع

```
supabase/migrations   قاعدة البيانات (جداول، صلاحيات RLS، دوال سير العمل، الفوترة، التقارير، الموارد البشرية)
supabase/seed         بيانات العرض وحذفها
supabase/tests        اختبارات الصلاحيات وسير العمل
src/app               الصفحات (الموقع، patient, doctor, reception, billing, admin, hr, me, print, verify)
src/app/actions       Server Actions
src/components        مكونات الواجهة
src/lib               الإعدادات، الترجمة (i18n)، الإشعارات، النصوص القانونية
```
